# 登录验证码弹窗设计

## 背景

当前后台管理登录、OAuth 认证登录和钉钉首次登录的“绑定已有账号”流程，都将验证码入口直接展示在账号表单内。用户需要先单独完成验证码，再次点击提交，操作链路不连贯。

本次调整将验证码变为提交动作中的安全验证步骤：用户点击提交后弹出验证码，验证成功后自动继续原登录或绑定操作。

## 范围

包含以下流程：

- 后台管理账号密码登录。
- OAuth 认证页面的账号密码登录。
- 钉钉首次登录中的“绑定已有账号”。

不包含以下流程：

- 钉钉首次登录中的“创建新账号并登录”。
- 点击“钉钉快捷登录”后跳转至钉钉授权页的流程。
- 后端验证码或登录接口协议调整。

## 交互流程

### 后台管理登录与 OAuth 登录

1. 用户填写用户名和密码并点击提交。
2. 前端只执行本地表单校验，不调用登录接口。
3. 本地校验通过后打开验证码弹窗。
4. 用户完成验证码，前端获得 `captchaId` 和 `captchaCode`。
5. 验证码弹窗自动关闭，并立即调用登录接口；请求同时携带用户名、加密密码、`captchaId` 和 `captchaCode`。
6. 登录成功后沿用当前登录初始化或 OAuth 跳转逻辑。

### 钉钉绑定已有账号

1. 用户在“绑定已有账号”页签填写用户名和密码，点击“验证并绑定”。
2. 前端先执行字段必填、长度等本地校验，不调用登录接口。
3. 本地校验通过后打开验证码弹窗。
4. 验证码通过后立即调用密码登录接口，并携带验证码结果。
5. 密码登录成功后使用返回的临时登录令牌继续调用钉钉绑定完成接口。
6. 绑定完成后沿用当前登录初始化逻辑。

“创建新账号并登录”仍直接执行现有创建流程，不展示验证码。

## 组件设计

验证码能力调整为受控弹窗组件，由业务页面管理打开状态，并提供以下清晰接口：

- `open`：控制弹窗显示。
- `onCancel`：用户关闭弹窗时通知调用方。
- `onSuccess`：验证码校验通过后返回 `captchaId` 和 `captchaCode`。

组件负责验证码获取、刷新、滑块或文字点选、服务端校验及弹窗内的加载和错误状态。业务页面只负责决定何时打开弹窗，以及在 `onSuccess` 后继续哪一个提交动作。

验证码仅在弹窗打开时获取，避免页面加载时提前创建无用验证码。每次重新发起登录或绑定均进行一次新的验证码验证，不复用上次的验证结果。

## 状态与异常处理

- 用户名或密码未通过前端校验：展示现有字段提示，不打开验证码弹窗。
- 验证码加载失败：保留弹窗并提示用户重试。
- 验证码校验失败：刷新验证码，保留弹窗，不调用登录接口。
- 用户主动关闭验证码：取消本次提交，保留账号表单内容。
- 验证码通过：关闭弹窗并立即进入业务提交状态，防止重复点击。
- 登录或绑定失败：由现有请求层展示业务错误；本次验证码结果作废，下次提交重新验证。
- OAuth 授权请求已失效：保持现有禁用提交和错误处理逻辑，不打开验证码弹窗。

## 可访问性与样式

- 使用 Ant Design `Modal` 提供焦点管理、键盘关闭和遮罩语义。
- 验证码图片保留准确的替代文本；刷新和滑块操作保留可识别的按钮语义。
- 新增或调整的样式继续放在对应的 `*.module.less` 文件中，不使用 CSS-in-JS。
- 提交与验证期间显示加载状态，并禁用会导致重复请求的操作。

## 测试与验收

重点验证以下场景：

- 三个目标流程点击提交后才请求并展示验证码。
- 账号字段无效时不打开验证码、不调用登录接口。
- 验证码成功后无需再次点击即可自动登录或绑定。
- 登录请求始终同时携带 `captchaId` 与 `captchaCode`。
- 验证码失败或取消时不调用登录接口。
- 钉钉“创建新账号并登录”不展示验证码，行为保持不变。
- 登录或绑定失败后再次提交会获取并校验新验证码。
- 前端类型检查及相关构建通过。
